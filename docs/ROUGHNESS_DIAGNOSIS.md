## 1. 先看判据 —— headline 指标看不见你要修的东西

`fid_k` 来自 `eval/metrics.py`。它在算 FID 前用 `normalize_separately` 对**每个分布按它自己的
逐维均值/标准差**标准化。标准化之后两边 μ=0、tr(Σ)=72.2408 恒等，于是它化简成

```
fid_k = 144.4816 − 2·tr( sqrt(S_pred · S_gt) )        S 是相关矩阵
```

**它只比较两个集合的 72 维相关结构。** 三条实测（在 `runs/t18_draft/random_self/features` 上）：

| 对生成集合做什么 | fid_k 变化 | 意味着 |
| --- | ---: | --- |
| 把 300 条生成的顺序打乱（摧毁每条与它真值的配对） | **−2.4e−10** | 看不见"这支舞是不是跳给这首歌的" |
| 逐维仿射：尺度 U(0.1,10)、平移 N(0,100) | −6.5e−12 | 看不见幅度 |
| 把所有特征减半 | **逐位相同** | 看不见能量大小 |

推论，两条都要记住：

1. **任何逐条配对的代理指标都预测不了 fid_k**（测地距离、跟随度），因为它们量的东西
   只能通过池化的相关矩阵进入公式，没有单调关系。2026-08-18 的 medoid 事故就是这么来的。
2. **优化 fid_k 不会让动作变好看。** 这不是推断，是测量：见 §4 的 dn005。

### 1.1 四种判据不完整，2026-08-18 之前每种都发生过至少一次

* **样本是排序前缀而不是抽样。** `runs/t_stride_sweep/clips24.txt` 那 24 条是另一个 600 条池子的
  排序前缀，与 300 条协议只重叠 **11 条**，而它的真值比语料真值**快 1.41×、抖 1.41×**
  （`median_of_all` 0.758 对 0.539；jerk 508 对 360）。**所有以"真值 1.063 / 508"标定的成本闸
  都偏了这个倍数**，包括 `tools/smooth_generated_motion.py` 的 `--max-speed-loss`。
* **只报一个特征族。** `fid_k`（kinetic，速度）与 `fid_m`（manual，姿态几何）会反向。
  `random` 检索在 fid_k 上赢、在 fid_m 上 4 格输 3 格 —— 那个"改进"是速度伪影。
* **只报一个速度口径。** 生成动作的关节速度剖面是平的（§3.A），于是
  `median_of_frame_mean` 会把"每个关节都偏快"读成"速度正好"；换 `median_of_all` 结论反向。
  `tools/score_generation_diagnostics.py` 的 docstring 自己写着这两个口径在真值上差 1.4×。
* **没有配对检验。** 逐 clip 配对置换检验（交换哪条臂进集合）会把看起来一致的差打回去：
  `random` 在 headline 那格 **p = 0.206**。

### 1.2 判据已经在工具里了：`tools/judge_arm.py`

一条命令给一条臂一个裁决，带齐两族 FID、逐族噪声带、逐 clip 配对置换 p、和粗糙度八轴。
**判据顺序是：先过噪声带 → 再看两族是否同向 → 再看 p。** 这个顺序是被一次真实错误纠正出来的：
第一版先测两族同向，于是把 `gapfill interpolate` 那条（两族 +0.45% / −0.89%，都在各自带内）
判成"两族分歧"，又把 `no-plan` 的 −41% kinetic 退化吞掉，因为 manual 往反方向漂了 4%。
**一个在自己噪声带内的族没有符号可供分歧。**

裁决取值：`IMPROVED` / `REGRESSED` / `UNDETERMINED` / `SPLIT_FAMILIES` / `AXES_DISAGREE`。
最后一个是给 dn005 那类臂的 —— fid 退但可见轴向真值走，**不能当成单纯的退化报**。

**验收命令 `--replay`**：它重跑 2026-08-18 那 9 条臂，并断言那天手工定下的裁决。
`random` 不许出 `IMPROVED`；`medoid` / `gapfill` / `root_xy` 必须落在"无结论"；
`no-plan` 必须是退化。**改判据逻辑之后如果这些不再成立，是工具坏了，不是发现了什么。**
runs/ 不在 git 里，所以缺目录时它 **REFUSED 退出而不是跳过** —— 一次跳着跑还返回 0 的验收，
正是本仓一直在付代价的那种闸。

2026-08-18 的验收输出（`runs/t23_judge/replay_20260818.json`）：

| 臂 | 裁决 | 判它的那一条 |
| --- | --- | --- |
| noplan s1 / s2 | AXES_DISAGREE | kinetic −62.5% / −41.1%，p=0.000/0.001；但六条粗糙度轴向真值走 |
| dn005 s1 / s2 | AXES_DISAGREE | kinetic −63.9% / −76.7%；八轴里六条向真值 |

**逐族噪声带是测出来的，不是写死的**（`--noise-pair` 给一对同配置不同种子的臂）：

| | kinetic | manual |

实际作用是**否决**（两族反向时挡住结论），不是判决。引 fid_m 时要记得这条。

## 2. 300 条配对协议

`tools/run_draft_ab.sh <name> <gpu> [flags]`。固定：同 300 条名单
（`runs/t14_oracle/clips340.txt`，`manifest.names` sha256 前 12 位 `090f47939635`）、

### 2.1 种子噪声带

| --- | ---: | ---: |
| SELF+duration | 3.272 → 3.069 | 3.551 → 3.454 |
| **|Δ|** | **0.203（6.2%）** | **0.097（2.7%）** |

**低于这个带的差不是结论。**

### 2.2 ORACLE 只能和 ORACLE 比

`plan_source=ORACLE_GROUND_TRUTH_PLAN` 同时拖动五样东西：`plan_stride 15→340`、
`plan_fusion vote→none`、`ground_truth_labels`、`target_motion_selection`，

`short_batch_mode`。**ORACLE 与 SELF 之间的差不能归给"计划是否正确"。**

## 3. 已确立 —— 三个症状是一个：根平移通道

### A. 位置抖动几乎全是共模的

**先看这一条，它把后面所有东西重排了。** 把 jerk 拆成根平移与关节相对两部分
（`tools/probe_roughness_structure.py`，按 clip 配对、真值截到同样 340 帧）：

| 臂 | 根 jerk | /真值 | **关节相对** | **/真值** | 根占全身 | 世界 CV | 根相对 CV |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **真值** | 91 | 1.00 | 398 | 1.00 | 20.7% | 0.573 | **0.737** |
| 不做计划 | 145 | **1.58** | 92 | **0.23** | 87% | 0.325 | 0.658 |
| **基线 s1 / s2** | 1695 / 1666 | **18.55 / 18.23** | 404 / 450 | **1.01 / 1.13** | 90% | 0.286 | **0.743 / 0.727** |
| ORACLE | 1744 | 19.08 | 458 | 1.15 | 88% | 0.278 | 0.735 |
| root_xy / gapfill / medoid / random | 1601–1712 | **17.5–18.7** | 405–412 | 1.02–1.03 | 88–91% | 0.283–0.290 | 0.738–0.743 |
| dn005 | 918 | **10.04** | 326 | 0.82 | 90% | 0.387 | 0.800 |

三条读法：

1. **跳舞的部分是对的。** 关节相对 jerk 1.01× 真值；根相对的关节间速度 CV 0.743 对真值 0.737，
   **无法区分**。
2. **坏的是根平移一条通道**：18.6× 真值，占全身 jerk 的 90%。
3. **「关节能量剖面平」和「根在抖」是同一件事说两遍。** 世界坐标下 CV 0.286 对真值 0.573，
   看起来每个关节速度差不多；把根减掉，两边一样。一个加在所有关节上的共模项按算术会压扁关节间的差。
   **脚滑同理** —— 踝速 3.24×、地面路径 3.82× 而净位移 0.26×，就是整个人在原地共模抖动。

**所以此前写的「三条症状」应当读成一条。** 幅度仍然不是问题（伸展 1.07×、转身 1.00×）。

### B. 抖动是模型生成的，不是从 draft 抄的，也不在 draft 侧任何开关的射程内

* **draft 自己的根比真值还平滑**：按推理那条一模一样的检索重建、同一条反归一化 + FK 解码，
  40 条上 draft 根 jerk **65**（真值 91），关节相对 321；**生成的根是它的 27.3×**。
* **draft 侧每一个开关都动不了它**：根连续性 18.62、gap 填充 17.51、medoid 17.67、random 18.73、
  **真值计划 19.08** —— 全在 17.5–19.1×。
* **不给 draft 就不发生**（1.58×），但那时舞也没了（关节相对 0.23× 真值）。
* **只有训练侧的改动移动了它**：dn005（σ 0.25→0.05）减半到 10.04×。

**所以：draft 同时打开了舞蹈（关节相对 0.23× → 1.01×）和根抖动（1.58× → 18.6×）。**

### C. 频谱与解剖学：宽带高频，且不在旋转里

* **频谱**（Welch，segment 128，根相对）：0–6 Hz 生成是真值的 **0.8×**，6–10 Hz **4.8×**，
  10–15 Hz **7.6×**。低频略弱、高频高几倍 —— 加性高频成分，不是「同一支舞能量更大」。
* **角速度 jerk 的关节间 CV：生成 0.539 对真值 0.556（0.97×）**，而且逐关节看生成**低于**真值。
  **旋转比真值还平滑。**
* **位置 jerk 比与力臂的相关是 −0.809** —— 越靠近根越糟，与「rot6d 上等权 MSE 忽略力臂」
  预测的方向**相反**。那条机制假设被这两个数一起否掉了。

### D. 目标函数与这条通道的关系

151 维 = **4 触地 + 3 根位置 + 144 rot6d**（`infer_atomic.py:34`）。第 4:7 维是**绝对根位置**
（`decode_motion` 直接把它当平移喂给 FK；`build_draft` 的 docstring 也记着「原型按它在自己录像里的
绝对根位置粘贴」）。

```python
denoising  = F.mse_loss(prediction, clean_motion)          # 151 维等权 -> 根只占 3/151
transition = self.transition_loss(prediction, boundaries)  # 只在段边界
```

**逐帧独立地回归绝对位置，没有任何速度/加速度项耦合相邻帧。** 这与「宽带高频、集中在根」一致。
但它**不能单独解释**为什么同一个模型在没有 draft 时根是平滑的（1.58×）——
**那就是第 5 节的开放问题。**

### E. 训练侧能移动可见轴，且与 fid_k 反向

`dn005` = 训练时加在 draft 上的噪声 σ 从 0.25 降到 0.05 重训。300 条双种子：
根 jerk 18.55× → **10.04×**、关节速度 2.13× → 1.69×、CV 0.294 → 0.381，
而无泄漏 fid_k 从 3.551/3.454 退到 **5.820/6.103（+64% / +77%）**，比不做计划还差。
跟随度 4.92/4.92 对基线 5.33/6.48（持平），所以「更抄错类原型」这个机制被它自己的对照排除。

### F. 只过滤根平移：可见轴全线改善，代价可证明为零

`tools/smooth_generated_motion.py --channels root`：只对 3 个根平移维度做 Savitzky-Golay，
**旋转逐位不动**（等于把身体刚性地重新坐在一条平滑的根轨迹上）。300 条、w=21/order 2：

| | 全身 jerk /真值 | 关节速度 /真值 | **关节相对 jerk** | 地面路径 /真值 | 踝速 /真值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 生成 原样 | 5.66× | 1.667 | 433.762 | 3.21× | 2.20× |
| **根低通 w=21** | **1.45×** | **1.115** | **433.761**（变化 0.0002%）| **1.10×** | 1.45× |

**此前每次平滑都要付的「把舞跳没了」的代价在这里按构造不存在**，而且这是被检查出来的不是被声称的：
`--max-articulation-change` 会在关节相对 jerk 变动超过 1% 时判否。

**成本闸因此改了，连同理由一起改**：`--channels all` 仍用原来的「速度掉太多就判否」，
因为在那条路径上「速度掉」和「舞被删掉」分不开；`--channels root` 分得开（关节角可证明未动），
所以它判的是**是否更靠近真值**而不是**是否变慢** —— 未过滤的臂本来就比真值快 58%，
用「速度掉了」去判它等于因为它做对了事而判否它。

**但 fid_k 判它退 28%**（无泄漏 4.534 对 3.551，配对置换 **p = 0.230**，即没分辨出来），
fid_m 反而改善（3.815 对 3.887）。`judge_arm` 给出 **UNDETERMINED**。
**这是第三次、也是最干净的一次看到「可见轴与 fid_k 反向」** —— 一个可证明不改变任何关节角的变换，
把 8 条可见轴里的 7 条推向真值，headline 指标说它更差。

## 4. 已推翻 —— 不要重新捡起来

每条给三行。只写现在的说法，读的人无法判断你是不是又错了一次。

### medoid 是当前最高优先级
* **原说法**（worklog:6409）：val-60 上测地距离比"时长最近"近 10.79%，收回类内 oracle 余量 51.0%，60/60 全胜。
* **推翻它的**：ORACLE 计划下 300 条 fid_k 更差（清洁 +0.579 / 全集 +0.320，80% 子采样 400 次**符号 100% 一致**）。
  而选中它的那把尺子（`geodesic_rad`）只读第 7:151 列，**根位置第 4:7 维从不进入计算**。
* **现在**：真值计划下 medoid 确实更差；SELF 计划下是平局（清洁 +0.184 但全集 −0.016，
  同一批生成换子集变号，符号一致性 58%）。**撤下优先级，不再推进。**

### random 检索比"时长最近"好
* **原说法**：无泄漏 fid_k 两个种子一致更低（−6.3% / −11.0%）。
* **推翻它的**：① `fid_m` 上 4 格输 3 格；② 配对置换 headline 那格 **p = 0.206**；
  ③ 机制 —— `_values_at`（`infer_atomic.py:277`）把原型重采样到段长，duration 只有 10.2%
  被重采样、random 是 97.3%（中位 1.48×），把 draft 调**慢 11%**，而生成本来就快 14.45%。
* **现在**：判否。**但它挖出一件真东西：`_values_at` 的时间重采样是一个隐式速度旋钮**，
  由检索规则当副作用控制，没有开关、不进 manifest、没有判据。要测它得用速度判据单独测。

### dn005 判否，因为速度掉 23% 低于真值
* **原说法**（worklog:6178）：速度 0.829 对真值 1.063，低于真值，成本闸触发。
* **推翻它的**：那个真值来自 24 条排序前缀 + `median_of_frame_mean` 口径。300 条 + `median_of_all`
  下 dn005 是真值的 **1.69×** —— 从来没有低于过，基线是 2.13×。
* **现在**：**判否成立，理由换掉** —— 判它的是 fid_k（+64%/+77%），而这个数在 2026-08-18 之前
  根本没算过（worklog 那一行是"—"）。

### 三条症状（抖 / 剖面平 / 脚滑）是三件事
* **原说法**（本文档 2026-08-18 上午版）：可见缺陷是三条，各需一种修法，先攻剖面平。
* **推翻它的**：把 jerk 拆成根平移与关节相对之后，关节相对 jerk 是真值的 1.01×、
  根相对的关节间 CV 0.743 对真值 0.737 —— **跳舞的部分无法与真值区分**。世界坐标下的
  「剖面平」与「脚滑」都是同一个共模根抖动的投影（§3.A）。
* **现在**：一条症状，一条通道。**先解决根平移。**

### 剖面平是因为 rot6d 上等权 MSE 忽略了力臂
* **原说法**：MSE 对每个关节的旋转等权、与力臂无关，所以末端的位置误差被骨架放大。
* **推翻它的**：这条预测两件事，两件都反了 —— 生成的角速度 jerk 关节间 CV 是 0.539 对真值
  0.556（不是更平），且逐关节**低于**真值；位置 jerk 比与力臂的相关是 **−0.809**（越靠近根越糟）。
* **现在**：旋转比真值还平滑，问题不在 144 个 rot6d 维里。

### 幅度保守（伸展 0.91×、转身 0.84×）
* **原说法**：24 条上伸展与转身双双低于真值。
* **推翻它的**：300 条重测 1.07× / 1.00×。
* **现在**：幅度不是缺陷，**从症状清单里删掉**。

### 推理端加在 draft 上的噪声是抖动来源
* **原说法**：`perturb_draft` 在 `sample()` 里也跑，σ=0.25 的逐帧白噪声进入输出。
* **推翻它的**：σ = 0 / 0.10 / 0.25 → jerk 1699 / 1687 / 1739，噪声内。
* **现在**：推理端无关；**训练**端的 σ 才有效（dn005 −43%）。

## 5. 开放 —— 问题变窄了，但还没关掉

**为什么 draft 条件化会让根平移通道抖 12 倍（1.58× → 18.6×），而同一批权重下的旋转输出
比真值还平滑？**

已经不在候选里的（各有对照）：不是抄 draft 的根（draft 根 jerk 65 < 真值 91）；
不是 draft 的根不连续（root_xy 18.62 ≈ 基线 18.55）；不是段边界（gapfill 17.51）；
不是类错（ORACLE 19.08，更高）；不是采样时加的噪声；不是拼接缝；不是野外语料。

还在候选里的两条，现在都要**只针对根通道**来问：

* **(a) 目标函数**：第 4:7 维是逐帧独立回归的绝对位置，只占 151 维 MSE 的 3/151，
  且没有任何项耦合相邻帧的根位置。
* **(b) 条件冲突**：draft 的根来自别人的录像、与查询的根在完全不同的位置范围，
  模型在「跟随它」和「音乐说该在哪」之间摆。

### E1（修订）：真值动作当 draft、mask 全 1

* 根 jerk 仍 **≥10×** 真值 ⇒ **(a)**，修法是根通道的目标函数（速度参数化 / 加速度项 / 提高 3 维权重）。
* 根 jerk 塌到 **≤2×** ⇒ **(b)**，目标函数无罪。

**新增一条更便宜的 E1b**：draft 的旋转照旧、**只把 draft 的根通道置零或置为查询自己的起点**。
它把「draft 的根让模型困惑」与「draft 的存在本身」分开，而 E1 分不开这两个。
两条都要 `infer_atomic.py` 加一个新开关，一条臂 8 分钟。

### 与根低通的关系

§3.F 的过滤是**缓解不是修复** —— 模型仍然吐出坏通道，只是事后重写。
它有用的地方在于：它证明了**关节相对运动已经够好**，所以根因确实只在这一条通道上，
而且如果 E1 指向 (a)，训练侧修好之后应当**不再需要这个过滤**，那就是训练侧修复的验收判据。

## 6. 已定位但还没修的代码缺陷

按"会不会误导下一个人"排序，都不是抖动的根因。

1. **`_blend_weights` 在 window 340 / stride 75 下自我覆盖**（`infer_atomic.py:687`）。
   `overlap = 340−75 = 265`，两次 `linspace` 赋值区间重叠，权重在窗内第 74→75 帧从
   **0.282 跳到 0.996**（典型逐帧步长 0.0038）。条件是 `2*(window−stride) > window`，
   150/15 也中。**修它是正确性，不是粗糙度** —— stride sweep 说去掉它反而更抖。
2. **`_values_at` 的时间重采样没有开关**，见 §4 的 random 条目。
3. **`MEDOID_CANDIDATE_CAP` 的等间隔抽样对 12.1% 的类退化成前缀截断**：
   `stride = len(candidates) // 24`，候选数在 24–47 之间时 stride=1，`picks[:24]` 就是前 24 个 ——
   正是它 docstring 声称要避免的。另：val-60 的代理用 cap 32，代码里是 24。
4. **`code_revision` 区分不出代码版本**：2026-08-18 那 12 条臂的 manifest 记的都是
   `d36de11 / working_tree_dirty: true`，而 `retrieval_rule` 与 `no_plan_conditioning`
   只存在于未提交的改动里。**唯一泄露代码被改过的证据是 manifest 键的有无。**
   dirty 树跑出来的产物需要一个内容级的代码指纹。
